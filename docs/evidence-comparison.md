# Full hold versus investigated release

Open `/evidence-comparison.html`, linked from the main Supply Yard header. This comparison uses the same $10-kit, receipt-linked engine as `/`. It does not use the earlier $50-kit optimization model at `/comparison.html`.

One start commits both local policies through three shifts. Both use the same cached sandbox payment reference; no checkout, capture or provider verification is repeated. The default is 36 merchants, seed 773, generated fees of 3%, assumed processing cost of 1% of gross, and assumed review expense of $0.25 per merchant per investigated shift. The native reference retains its recorded $3.70 fee on $100 gross; all other fees are modeled.

## Matched inputs and boundaries

Both independent worlds start with the same merchant profiles and $50 working capital per merchant. Exact order IDs, quantities, gross amounts, fees, supplier opening stocks, procurement prices and keyed delivery/evidence-availability draws match in every shift. The controller rejects changed inputs and records a match audit.

The policies change merchant cash, procurement and later deliveries. Consequently the records generated by those deliveries may differ; randomness is keyed consistently instead of forcing identical delivery outcomes. Neither investigator receives hidden physical outcomes.

Full hold makes no carrier or office queries. The reviewed side uses the existing scripted investigation. Starting the paired replay precommits these hypothetical policies, so the animation needs no extra approval per shift. This does not change provider reserves or use a new PayPal transaction.

`Net contribution = fees retained − processing cost − provider-funded refund shortfalls − investigation expense.`

Expenses are tracked in provider accounting, separate from merchant wallets. Review expense is charged once per merchant per investigated shift, including cases with no release. Static policies have no incremental investigation expense. Fees are retained after refunds under an explicit model assumption.

Orders are deliberately fixed, so fees cannot improve through higher customer retention or more demand. There is no churn, lifetime-value bonus, later chargeback model or reserve expiry. This is a bounded contribution calculation, not PayPal accounting profit or production ROI. With review cost set to zero, direct benefit is zero in the default fixture.

## Is it agentic?

The current implementation is a deterministic investigation workflow. It has no trained regression model, classifier, learned planner or LLM. The scripted roles use a fixed carrier-then-office sequence, exact ID checks and an authored reserve formula. A conventional workflow with the same retrieval and rules can reproduce it.

Agentic behavior and predictive ML are different dimensions. A regression or classification model could estimate loss or prioritize a case inside an agent. The proposed agent's responsibility would be choosing actions to acquire missing evidence, interpreting varying documents, revising hypotheses after contradictions and deciding when to stop or escalate. Money arithmetic, proof validity, limits and final authority stay deterministic.

A concrete proposed task: a carrier says a pallet arrived, an office reports only part of the order arrived, and a merchant supplies a free-form batch manifest. An investigator chooses to reconcile the manifest, identify which order lines need independent confirmation, and request only the unresolved evidence. It updates its next action when the response contradicts the first explanation. That capability is not implemented in this scripted POC.

Start with one investigator and deterministic verification. Several named agents are not justified just by narrating different positions. Independent reviewers or specialist agents would need to measurably reduce errors or cost to justify their extra coordination.

The next evaluation should hold cases and tool budgets constant across:

1. The current fixed retrieval workflow.
2. An ML-prioritized fixed workflow.
3. An adaptive investigator choosing its next tool/source.

Measure unsupported releases, unnecessary holds, recovered evidence, source-query cost, elapsed time and human escalations on unfamiliar cases. Better deliveries versus full hold establish a policy/evidence effect, not an agent advantage.

## Controls and validation

The UI exposes **Initial feed only** as a no-retrieval control and **Same scripted review** as an identical-treatment control. Both sides of the latter use the same data, retrieval, formula and expense; all outcomes and net benefit match exactly.

Eight new tests check exact matching, isolated reference queries, accounting, the default negative net result, equal-workflow zero difference, initial-feed control, cost sensitivity, pause/step behavior, changed-input rejection and a complete 120-merchant run. All 96 repository tests pass.

Browser playtesting covers a full default replay, all three shift rows, cost breakdown, source-reuse labeling and the identical-workflow control. The main saved order store still has one native completed capture.
